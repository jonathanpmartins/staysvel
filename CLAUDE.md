# Staysvel

Laravel package wrapping the Stays External API (vacation rental PMS). Users compose
calls like `Stays::booking()->reservations()->create([...])`.

## Commands

```bash
composer test            # pest
composer lint            # phpstan
composer serve           # testbench serve (workbench app)
composer build           # testbench workbench:build
./vendor/bin/pest --filter=GuestTest     # run a single test file
```

## Architecture

Entry point is the static `Staysvel\Stays` class (`src/Stays.php`). Each method returns
a domain class under `src/Lib/` (`Booking`, `Content`, `Calendar`, `Finance`, `Price`,
`Review`, `Setting`, `Translation`, `Doc`). Domain classes return feature classes
(e.g. `Booking::promoCodes()` → `Lib/Booking/PromoCode.php`). Every class extends
`Staysvel\Api`, which carries `$timeout` and exposes `$this->http()` / `$this->validate()`.

HTTP is centralized in `src/Http.php`, which dispatches through the `Http::stays()` /
`Http::staysXlsx()` macros registered in `StaysServiceProvider::boot()`. Those macros
handle Basic auth (base64 of `client_id:client_secret`) and prefix requests with
`/external/v1` (see `StaysServiceProvider::$prefix`). Never call `Illuminate\Http\Http`
directly — always go through `$this->http()`.

Swagger specs live in `swaggers/` split per domain — treat them as the source of truth
for endpoint paths, query params, and payload shapes when adding new calls.

## Validation pattern (important)

`Api::validate($parameters, $rules)` does NOT throw on failure. It returns either the
validated array OR an `Illuminate\Http\Client\Response` with status 422. Any method
that validates MUST check and short-circuit:

```php
public function create(array $parameters = []): Response
{
    $validated = $this->validate($parameters, [...]);

    if (is_a($validated, Response::class)) {
        return $validated;
    }

    return $this->http()->post('/reviews/guest', $validated);
}
```

See `src/Lib/Review/Guest.php` for the canonical shape. Returning the 422 response
keeps the public API consistent — callers always get a `Response` back.

## Testing patterns

Tests use `Http::fake()` (set up in `tests/TestCase.php::setUp`). Three helpers:

- `assertRequest(string $method, string $path, Response $response)` — asserts the
  HTTP call was sent AND that the response's effective path matches (with the
  `/external/v1` prefix applied via `makePath()`).
- `assertRequestNotSent(string $method, string $path)` — for validation tests that
  must short-circuit before hitting HTTP.
- `assertValidation(Response $response, string $field, string $errorKey, array $params = [])`
  — asserts the 422 shape and the localized error message.

Validation datasets are auto-generated by `Tests\ValidationRuleTransformer` from the
same rule strings used in the implementation. Pattern:

```php
dataset('guest create validation rules', function () {
    $transformer = new ValidationRuleTransformer([
        'day' => 'required|string|date_format:Y-m-d',
        // ...
    ]);
    return array_merge($transformer->toDataProvider(), [
        // extra cases the transformer can't express, e.g. max:5
        ['cleaningRating', ['cleaningRating' => 6], 'max.numeric', ['max' => '5']],
    ]);
});
```

Supported validations in the transformer: `required`, `email`, `array`, `boolean`,
`in`, `phone`, `zipcode`, `date`, `date_format`, `numeric`, `integer`, `file`,
`string`, `exists`. Anything else (min/max, nullable) must be added as extra rows.

## Configuration

Consumers set in `config/services.php`:

```php
'stays' => [
    'endpoint' => env('STAYS_ENDPOINT'),
    'client_id' => env('STAYS_CLIENT_ID'),
    'client_secret' => env('STAYS_CLIENT_SECRET'),
],
```

Tests override these in `TestCase::setUp()` with dummy values and `https://api.stays.net`.

## Conventions

- PSR-4: `Staysvel\` → `src/`, `Tests\` → `tests/`.
- Timeout propagates through the chain — every factory method does
  `(new X())->timeout($this->timeout)` so `Stays::timeout(30)->booking()->...` works
  at any position in the chain.
- When adding a new feature class: create it under `src/Lib/<Domain>/`, add a factory
  on the domain class, add a Pest test under `tests/Unit/<Domain>/<Name>Test.php`, and
  cross-reference the corresponding `swaggers/<domain>.json`.
- Keep brace style consistent with existing files (Allman — opening brace on its own
  line for classes and methods).
